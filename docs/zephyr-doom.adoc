= Zephyr-Doom

== Introduction

This is a port of https://en.wikipedia.org/wiki/Doom_(1993_video_game)[Doom (1993)]
for https://zephyrproject.org/[Zephyr RTOS].

The project is forked from https://github.com/NordicPlayground/nrf-doom[nrf-doom]
(commit https://github.com/NordicPlayground/nrf-doom/commit/2d42413b2c49cda7c60d3cd14b858df1b665533f[2d42413]),
which is forked from https://www.chocolate-doom.org/wiki/index.php/Chocolate_Doom[Chocolate Doom]
version 3.0.0.

The objective of this internship project is to develop a Zephyr port of the
game, making sure it can run on different System-on-Chips (SoCs). This endeavor
will be divided into several stages, presented as Minimum Viable Product (MVP)
packages.

Zephyr-Doom has only been tested with Shareware version of Doom 1.

=== Prerequisites

. Install the https://code.visualstudio.com/download[Visual Studio Code].

==== For nRF5340 dev kit

. Install the https://www.nordicsemi.com/Products/Development-tools/nRF-Connect-for-VS-Code/Download#infotabs[nRF Connect for VS Code] (or https://www.nordicsemi.com/Products/Development-software/nRF-Connect-SDK/GetStarted[nRF Connect SDK]).

==== For FRDM-MCXN947 dev kit

. Install the https://marketplace.visualstudio.com/items?itemName=NXPSemiconductors.mcuxpresso[MCUXpresso for VS Code].

=== Build
Project is using per-board defaults for CONFIG_FEATURE_DOOM_* to enable / disable specific peripherals (for example, BLE defaults on for the nRF5340 build) while remaining overrideable in prj.conf.

==== Game for nRF5340 dev kit

VS Code:

* *Visual Studio Code -> nRF Connect extension -> Add Folder as Application ->
Select `zephyrdoom` folder*
* *Visual Studio Code -> nRF Connect extension -> Applications ->
Add build configuration -> Select board target `nrf5340dk_nrf5340_cpuapp` ->
Build Configuration*

==== Game for FRDM-MCXN947 dev kit

VS Code:

* *Visual Studio Code -> MCUXpresso for VS Code -> Import Repository -> Remote -> Repository - MCUExpresso SDK, Revision - main, Name - mcuxsdk, Location - based on your preference*
* *Visual Studio Code -> MCUXpresso for VS Code -> Import Repository -> Remote -> Repository - Zephyr, Revision - v4.3.0, Name - zephyr, Location - based on your preference*
* *Visual Studio Code -> MCUXpresso for VS Code -> New Project Wizard -> Project Type - Zephyr -> Board - NXP FRDM-MCXN947 (CPU0)  -> Repository - zephyr repo imported in previous step -> Zephyr SDK - zephyr-sdk-0.17.4 (ARM) -> Project Name - zephyrdoom -> Location - based on your preference  -> Create Project*
* *Copy content of `zephyr-doom\zephyrdoom` folder to created project*
* *Visual Studio Code -> MCUXpresso for VS Code -> Projects -> zephyrdoom -> mouse right-click -> Build Project*

or build from the repository root using `west`:

[source,bash]
----
west build -b frdm_mcxn947/mcxn947/cpu0 -p auto zephyrdoom
----

==== Game for native_sim (PC)

The `native_sim` target builds the game as an ordinary Linux executable, with
the display in an SDL window and the host keyboard for input. No dev kit is
needed, and there is no game data to flash, because the WAD is linked into the
binary.

Build from the repository root using `west`:

[source,bash]
----
west build -b native_sim/native/64 -p auto zephyrdoom
----

Run it directly:

[source,bash]
----
./build/zephyr/zephyr.exe
----

Doom command-line arguments are passed through the `DOOM_ARGS` environment
variable, because the native simulator owns the real command line:

[source,bash]
----
DOOM_ARGS="-warp 1 -skill 3" ./build/zephyr/zephyr.exe
----

=== Flash

==== Game for nRF5340 dev kit

VS Code:

. Connect https://www.nordicsemi.com/Products/Low-power-short-range-wireless/nRF5340[nRF5340] dev kit.

. Flash game data (contains `WAD` file) to external flash (XIP), mapped at `0x12000000`. The recommended default is the pre-populated full external-flash image
`gamedata/qspi.hex` (8 MiB: WAD at offset 0 plus cached game
data). Flash it raw to the QSPI base — this erases and replaces the entire
external flash in a single pass:
+
[source,bash]
----
nrfjprog --family nrf53 --qspicustominit --program qspi.hex --verify
----

. Select game app.
+
*Visual Studio Code -> nRF Connect extension -> Applications ->
Select `zephyrdoom`*

. Flash the game.
+
*Visual Studio Code -> nRF Connect extension -> Actions -> Flash*

==== Game for FRDM-MCXN947 dev kit

VS Code:

. Connect https://www.nxp.com/design/design-center/development-boards-and-designs/FRDM-MCXN947[FRDM-MCXN947] dev kit.

. Flash game data (contains `WAD` file) to external flash (XIP), mapped at `0x80000000`. The recommended default is the pre-populated full external-flash image
`gamedata/mcxn947-qspi-full.bin` (8 MiB: WAD at offset 0 plus cached game
data). Flash it raw to the QSPI base — this erases and replaces the entire
external flash in a single pass:
+
[source,bash]
----
pyocd flash -t MCXN947VDF --base-address 0x80000000 gamedata/mcxn947-qspi-full.bin
----
+
Or from Windows powershell:
+
[source,bash]
----
& 'C:\nxp\LinkServer_25.12.83\LinkServer.exe' flash 'MCXN947:FRDM-MCXN947' load .\mcxn947-qspi-full.bin:0x80000000
----
+
Alternatively, `gamedata/qspi_nxp_80.hex` contains just the plain WAD at the
same base (`0x80000000`):
+
[source,bash]
----
pyocd flash -t MCXN947VDF gamedata/qspi_nxp_80.hex
----

. Flash the game.
+
*Visual Studio Code -> MCUXpresso for VS Code -> Projects -> Select `zephyrdoom` -> mouse right-click -> Flash the Selected Target*

=== Multiplayer

zephyr-doom joins Chocolate Doom 3.0.0 network games on all three targets:
native_sim, FRDM-MCXN947 over Ethernet, and nRF5340 dev kit over USB CDC-ECM.
It can only *join* a game, so a `chocolate-server` running on a PC is always
required.

A two-player game run entirely on the host is the quickest way to check that a
build works:

[source,bash]
----
# terminal 1
chocolate-server -port 2342

# terminal 2
DOOM_ARGS="-connect 127.0.0.1:2342 -nodes 2 -warp 1 -skill 3" ./build/zephyr/zephyr.exe

# terminal 3
SDL_VIDEODRIVER=x11 chocolate-doom -connect 127.0.0.1:2342 -iwad gamedata/doom1.wad
----

For the host prerequisites, the per-target network setup, the expected console
output and troubleshooting, see
https://github.com/Tietoevry-Create/zephyr-doom/blob/master/docs/multiplayer.adoc[multiplayer setup].
